## 〇、给客户的总回答（建议先读完本章）

客户提了五条产品需求。工程上它们不是五套独立系统，而是**同一艘船、同一套传感器、同一套控制软件的五种工作模式**。差别只是：目标从哪来、船上锁住哪几个量。

### 0.1 五条需求，分别能不能做

| 您的需求 | 结论 | 您怎么用 | 关键条件（不满足就做不像） |
|---|---|---|---|
| 远程控制（前后左右） | **能做** | 地面站摇杆 + 看视频 | 「左右」若指**船头不动地横移**，必须用四推进器；两台桨的「左右」其实是转弯前进 |
| 定点稳泊 | **能做** | 一键钉住，或松杆自动钉住 | 必须厘米级卫星定位。若还要求**船头方向也不变**，必须四推进器 + 双天线 |
| 定速巡航 | **能做** | 设定速度后松手 | 锁的是**相对地面**的速度，不靠螺旋桨转多快 |
| 定向巡航 | **能做** | 锁定船头朝向，可同时前进 | 锁的是**船头朝哪**，不是船漂向哪；必须双天线，电子罗盘不可用 |
| 按航线巡航（绕湖一圈） | **能做** | 地图上画航点，船贴着线走 | 与上面共用同一套导航，另加航点表；不自动躲船、不自动贴码头 |

**默认推荐配置**（在您书面确认第 0.5 节之前，按此报价和设计）：

- 船体能前后、左右平移、原地转（**四台固定角度推进器**）
- **双天线 GNSS/INS 组合导航**（高精度卫星定位 + 内部惯导，直接输出位置、速度、船头朝向）
- 地面站：摇杆、地图、视频、一键定点/定速/定向/航线
- 物料成本量级约 **7–20 万**（电子与动力，不含研发与船体加工），典型约 11 万；若定点允许船头自由转动，可降到双桨方案，约 3–9 万

### 0.2 选用什么传感器、获取什么数据

**核心导航只买一套，五项功能共用。** 不要按功能各配一套 GPS。

| 装什么（客户说法） | 船上实际拿到的数据 | 没有它哪条会垮 |
|---|---|---|
| **双天线高精度卫星定位组合导航（GNSS/INS）** | 位置（厘米级）、对地速度、船头朝向、姿态；卫星短暂中断时惯导还能撑几十秒 | 定点、航线、定向全部没有可靠依据 |
| **每台推进器的转速和电流** | 桨转没转、电流大不大、是否堵转 | 不用于「船走了多快」；用于检查力有没有使出来、桨有没有缠上 |
| **电池电量** | 电压、剩余电量 | 低电无法自动返航 |
| **前视摄像头** | 实时画面 | 遥控时人看不见周围。**本期不做自动避障**，摄像头就是操作员的眼睛 |
| **测深 + 作业前水深图** | 船前水深、禁航区 | 浅水湖泊容易搁浅 |
| **风速仪** | 相对风速风向 | 定点时风力变化快，单靠位置误差反应不过来 |
| **漏水报警** | 舱内进水 | 安全底线 |

**不要用的**：普通手持 GPS、电子罗盘当主航向、用螺旋桨转速反推「现在走多快」。船上电机磁场会把罗盘带偏十几度；有水流时桨转得快，船相对岸边可以几乎不动。

控制软件真正拿去做决定的，只有融合后的 **6 个数**（约每秒 100 次）：东西/南北位置、船头朝向、前进速度、横移速度、转艏快慢。五种功能都吃这 6 个数，只是目标来源不同。

### 0.3 数据怎么处理、怎么决策，让船动起来

```
您在地面站：推杆 / 按定点 / 设速度 / 锁船头 / 画航线
        │
        ▼
船上先问：卫星定位现在靠不靠谱？电量、水深、围栏、链路是否正常？
        │  不够格 → 拒绝进入定点，或降级、停车、返航，并告诉您原因
        ▼
比较「现在这 6 个数」和「这一模式的目标」
        │
        ▼
算出船该往前/往后、往左/往右、该转多少力
        │
        ▼
四台推进器执行；同时用转速电流检查「指令有没有变成力」
```

| 模式 | 目标从哪来 | 船锁住什么 | 您能看到的效果 |
|---|---|---|---|
| 遥控 | 摇杆 | 速度或推力 | 推哪走哪；松杆可自动钉住 |
| 定点 | 按钮或松杆瞬间的位置 | 位置 +（默认）船头 | 图上钉住，风流下保持 |
| 定速 | 您设的速度 | 对地前进速度 | 顺流也不会越跑越快 |
| 定向 | 您设的朝向或当前船头 | 船头朝向 | 船头钉住，可同时前进 |
| 航线 | 地图航点 | 贴着航线走 | 绕湖一圈能回到起点附近 |

卫星定位质量不够时：**不允许进入精密定点**；短暂中断靠组合导航里的惯导维持并持续报警；超过约 1 分钟停车，等您接管。推力不够把船头也锁住时：先保位置、允许船头偏一点，再主动顶流，再不行就返航——**不会硬撑到失控**。

数据处理里必须做对、但客户侧不必关心公式的三件事：天线到船心的距离要量准、全船时钟要对齐、风流要当成「一直推着船的力」提前抵消。这三件事做错，后面怎么调参数都表现为「定点晃、航线蛇行」。

### 0.4 本期包含、不包含（避免验收争议）

**包含**：上述五项模式；失联停车/返航；低电返航；浅水限速与围栏；推进器单台故障后降级返航（四推方案）；地面站显示位置误差、是否还锁得住。

**不包含（除非另行立项）**：

- 自动识别并躲避其他船、漂浮物、游泳者（无雷达/激光/AI）
- 自动侧向贴靠码头
- 桥下/密林长时间无卫星的作业（惯导只能短时撑住）
- 用电子罗盘或桨转速代替卫星航向与对地速度

### 0.5 请您先书面确认的三件事

不确认这三件，**报价、推进器台数、电池、船体都会变**。完整清单在第十五章，但商务和技术启动前必须先拍这三条：

## 一、功能定义与工程翻译

### 1.1 五种工作模式

客户侧表述与推荐配置见第〇章。以下是工程定义：五种工作模式本质是**同一套导航与控制系统的五种"参考值来源"**，而不是五套独立系统。

| 功能需求 | 工程模式 | 被控量（闭环对象） | 必需的状态量 |
|---|---|---|---|
| 远程控制（前后左右） | MANUAL 遥控 | 无闭环，或速度/角速度弱闭环 | 无，或 u, v, r |
| 定点稳泊 | DP 动力定位 | 位置，可选叠加艏向 | x, y, ψ, u, v, r |
| 定速巡航 | SPEED HOLD | 纵向速度 u | u |
| 定向巡航 | HEADING HOLD | 艏向角 ψ | ψ, r |
| 按航线巡航 | AUTO 航点跟踪 | 跨航迹误差 + 速度 | x, y, ψ, u, r |

> **设计要点**：一套状态估计 + 一套分层控制（制导 → 控制 → 推力分配），五种模式只是参考值来源不同。任何"每个功能配一套硬件"的方案都是设计失误。

### 1.2 运动模型

三自由度水面船模型（NED 坐标系，船体系 x 前 y 右 z 下）：

```
位置/姿态：η = [x, y, ψ]ᵀ
速度：     ν = [u, v, r]ᵀ      （纵荡、横荡、艏摇角速度）

η̇ = R(ψ) ν
M ν̇ + C(ν)ν + D(ν)ν = τ + τ_env

控制输入：τ = [τ_X, τ_Y, τ_N]ᵀ   （纵向力、横向力、艏摇力矩）
```

### 1.3 一条决定全船路线的判据

**"定点时是否要求锁定艏向"是整个方案的分水岭**，它直接决定推进构型、传感器等级、电池容量和成本量级：

| 若定点允许艏向自由 | 若定点要求锁定艏向 |
|---|---|
| 2 个控制输入即可（欠驱动），双桨差速可行 | 必须 3 个输入独立可控（全驱动） |
| 船可自动顶流，环境力作用在**正面投影**上 | 最恶劣时环境力作用在**侧面投影**上，可放大 4~7 倍 |
| 推进器 2 台小功率，24V 系统 | 推进器 4 台大功率，48V 系统 |
| 定点功耗与巡航同量级 | 定点功耗可达巡航的 4~8 倍，直接冲击续航 |
| 成本量级 3~6 万 | 成本量级 7~20 万 |

欠驱动船只有 2 个控制输入却要控制 3 个自由度，**无论算法怎么写都无法同时锁定位置和艏向**——这是自由度不足的数学事实，不是调参问题。

## 二、推进构型设计路线

### 2.1 驱动能力与自由度

| 类别 | 独立控制输入 | 可控自由度 | 零航速下的能力 |
|---|---|---|---|
| 单桨 + 舵 | 1（推力，舵靠水流生效） | 1.5 | 几乎无控制能力 |
| 双桨差速 | 2（合推力、差力矩） | 2 | 可转艏、可进退，**不能横移** |
| 双桨 + 艏侧推 | 3 | 3 | 全向可控（低速有效） |
| 四推矢量 | 4（含 1 维冗余） | 3 | 全向可控 + 故障冗余 |
| 双方位吊舱 | 4（2 推力 + 2 转角） | 3 | 全向可控，动态受转角速率限制 |

### 2.2 路线 A：单桨 + 舵

**原理**：单螺旋桨提供推力，舵面在水流作用下产生转艏力矩。

- **优点**：成本与能耗最低；结构最简单；适合长航程
- **缺点**：**零航速无操纵性**（无水流则舵失效）；倒车时舵效反向；不能定点
- **能实现**：定速巡航、定向巡航、航线巡航（需保持最低舵效航速）、简单遥控
- **不能实现**：定点稳泊、低速精确机动、原地掉头
- **适用**：长距离水文/水质走航测量、河道巡线，且**无定点需求**
- **不适用**：需要在目标点停留作业、需要在狭窄水域机动

### 2.3 路线 B：双桨差速（欠驱动）

**原理**：左右两台推进器，同向出力产生纵向推力，差动出力产生转艏力矩。

```
τ_X = F_左 + F_右
τ_N = (F_右 − F_左) · b/2       b 为桨间横向距离
τ_Y = 0                          ← 横向力恒为零，这是全部限制的根源
```

- **优点**
  - 结构最简单，**无机械转向机构，可靠性高**
  - 成本最低（2 台推进器 + 2 路电调），能耗最低，续航最优
  - 桨小、可浅安装，**对浅吃水适配性好**
  - 生态成熟：ArduPilot Rover / Pixhawk 原生支持 skid-steering，开发周期最短
  - 零航速可原地掉头（与路线 A 的关键区别）
- **缺点与限制**
  - **不能产生横向力**，无法横移
  - **无法同时锁定位置与艏向**
  - 强横流下贴线航行必须靠偏转船头（侧偏角）补偿，船头不指向航线方向
  - 靠泊需要"前进-后退-转向"多次调整，操作难度高
- **能实现**：遥控（前后 + 转向）、定速、定向、航线巡航、**顶流定点（艏向自由）**
- **不能实现的场景（关键）**

| 场景 | 为什么不行 |
|---|---|
| 定点时船头必须朝固定方向（如对准岸基设备、传感器指向） | 自由度不足 |
| 侧向贴靠码头 / 自动靠泊 | 无横向力，无法平移贴岸 |
| 狭窄水道内原地侧移避让 | 同上 |
| 要求船头始终对准航线的高精度巡检 | 只能靠侧偏角，姿态与航向不一致 |
| 需要精确控制船体三自由度姿态的作业载荷（如定向声呐） | 位置与艏向不能解耦 |

- **顶流定点（Weather-Vane DP）**：差速构型下的定点解法是**把艏向当作被利用的自由度而不是被控量**——主动转向使船头顶住环境合力方向，再用纵向推力维持位置。此时环境力作用在正面投影上，推力需求最小，能耗最优。典型精度 ±1~2 m（RTK FIX 下可优于 ±1 m）。**这是欠驱动船唯一正确的定点策略。**
- **适用**：巡航为主、定点为辅且允许船头自由摆动、成本与续航敏感、开阔水域
- **不适用**：任何需要位置与艏向同时约束的场景

### 2.4 路线 C：双桨 + 隧道艏侧推

**原理**：保留双桨差速的高效直航，增加艏部横向隧道推进器补齐横向自由度。

- **优点**：巡航效率接近双桨方案；横向能力按需使用，不影响直航能耗；技术成熟（借鉴常规船舶）
- **缺点**
  - **对吃水有硬性要求**：隧道中心通常需位于水线下 1.0~1.5 倍隧道直径处
  - 浅吃水时隧道直径受限、推力不足，且船体纵摇易**吸气（ventilation）导致推力瞬间归零**
  - 隧道推力方向固定在艏部，艉部横向能力仍缺失，纯横移需与主推配合
  - 增加船体开孔与阻力
- **可用性判据**

| 吃水 | 可行隧道直径 | 大致推力 | 结论 |
|---|---|---|---|
| ≥ 0.5 m | φ150~200 mm | 15~30 kgf | 可行，推荐 |
| 0.35~0.5 m | φ100~150 mm | 5~15 kgf | 勉强，需专项验证吸气风险 |
| < 0.3 m | ≤ φ100 mm | < 5 kgf | **不可行** |

- **适用**：吃水 ≥0.4 m 的中大型船、以巡航为主但偶需侧移靠泊
- **不适用**：浅吃水小型船（本类项目常见约束）

### 2.5 路线 D：四推矢量固定布置（全驱动）

**原理**：4 台推进器固定安装，轴线与船体纵轴成 ±45°，推力矢量正交分解后可合成任意方向的力与力矩。

```
        艏
   ┌─────────────┐
   │ ↗         ↖ │
   │  P1       P2 │
   │    船  体     │
   │  P3       P4 │
   │ ↖         ↗ │
   └─────────────┘
        艉

                     P1(艏左) P2(艏右) P3(艉左) P4(艉右)
τ_X       [ cos45    cos45    cos45    cos45  ]   [F1]
τ_Y   =   [ sin45   −sin45    sin45   −sin45  ] · [F2]
τ_N       [  m1       m2       m3       m4    ]   [F3]
                                                   [F4]
m_i 为各推进器推力对重心的力矩臂，由安装位置与角度决定
```

- **优点**
  - **无机械转向机构**，可靠性高、开发周期短
  - 可浅浸没安装，**适配浅吃水**
  - **单台故障后剩余 3 台仍可维持三自由度控制**（降级运行）
  - 分配矩阵为常数矩阵，可离线预计算伪逆，实时性好
  - 全部采用货架产品，无定制件
- **缺点**
  - 直航有 cos45° ≈ 0.707 的分量损失，**效率比双桨低 15~25%**
  - 4 台推进器的成本、功耗、线束复杂度显著上升
  - 冗余会产生互相抵消的"内力"，需在分配算法中抑制
  - 安装角误差直接进入分配矩阵，**±3° 误差即产生明显运动耦合**（想横移却带转艏）
- **效率补偿**：巡航时令四台协同产生纯纵向力、横向分量互相抵消，实测损失可控制在 15% 内；或采用非对称角度（如 ±30°）偏向直航效率，代价是横向能力下降
- **适用**：需锁艏向定点、浅吃水、开发周期紧、需要故障冗余
- **不适用**：续航为最高优先级且不需横向能力的场景

### 2.6 路线 E：双方位吊舱（Twin Azimuth）

**原理**：两台推进器各自可 360° 转向，通过"推力 + 转角"组合实现三自由度控制。

- **优点**：**巡航效率最高**（推力全部指向航向）；推进器数量少、能耗低，对长续航最有利；横向与回转能力强
- **缺点**
  - 需防水转向机构（舵机 + 密封），**是整船最主要的故障点**
  - 推力分配是**非线性优化问题**，且转角速率限制引入动态滞后，快速换向能力差
  - 无故障冗余：任一转向机构卡死即失去全驱动能力
  - 定制件多，小批量成本高，调试周期长
- **适用**：续航指标严苛、批量较大、有成熟吊舱供应链、开发周期宽裕
- **不适用**：小批量样机、周期紧、要求高可靠性冗余

### 2.7 路线对照与选型决策树

| 维度 | A 单桨+舵 | B 双桨差速 | C 双桨+侧推 | D 四推矢量 | E 双方位吊舱 |
|---|---|---|---|---|---|
| 可控自由度 | 1.5 | 2 | 3 | 3（+冗余） | 3 |
| 锁艏向定点 | 不能 | **不能** | 可 | 可（±2~3°） | 可（±3~5°） |
| 横移能力 | 无 | 无 | 中（偏艏部） | 强 | 强 |
| 浅吃水适配 | 好 | **好** | 差 | 好 | 好 |
| 巡航能效 | 最优 | 优 | 优 | 低 15~25% | **最优（全驱动中）** |
| 机械可靠性 | 高 | **最高** | 中 | 高 | 中 |
| 故障冗余 | 无 | 无 | 无 | **有（4 选 3）** | 无 |
| 分配算法 | 平凡 | 平凡 | 线性 | 线性 QP | 非线性优化 |
| 开发周期 | 最短 | **短** | 中 | 中 | 长 |
| 物料成本量级 | 最低 | **低** | 中 | 中高 | 高 |

**选型决策树**

```
是否需要零航速下保持位置？
├─ 否 → 是否需要原地掉头？
│        ├─ 否 → 路线 A（单桨+舵）
│        └─ 是 → 路线 B（双桨差速）
└─ 是 → 定点时是否必须锁定艏向？
         ├─ 否 → 路线 B + 顶流定点（成本/续航最优解）
         └─ 是 → 吃水是否 ≥0.4 m 且允许船体开隧道？
                  ├─ 是 → 路线 C（巡航效率优先）
                  └─ 否 → 周期紧 / 要冗余 → 路线 D（四推矢量）
                          续航优先 / 可接受机械风险 → 路线 E（双方位吊舱）
```

> **典型工程结论**：小型浅吃水无人船若要求锁艏向定点，路线 C 被吃水排除、路线 E 被周期与可靠性排除，**实际可选项通常只剩路线 D**。若可放弃锁艏向，则路线 B 在成本、能耗、可靠性上全面占优。
>
> **对客户的默认**：第〇章在您确认「定点锁船头」之前，按路线 D 报价和设计。您书面确认不锁船头后，再切到路线 B。不要把上表五条路线并列交给客户挑选。

### 2.8 船体型式路线

| 型式 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **单体（排水型）** | 结构简单、成本低、侧向投影小（横向环境力小） | 同吃水下容积小，装不下大电池 | 载荷轻、续航要求中等 |
| **双体（Catamaran）** | 浅吃水下排水量大、横稳性极好、甲板面积大、直航阻力低、推进器有片体保护 | 结构复杂成本高、**侧向投影大 → 横向环境力高**、对锁艏向定点不利 | 大电池 + 大载荷 + 浅吃水 |
| **三体 / 带浮筒** | 稳性好、可折叠便携 | 阻力与结构效率折中 | 便携式小型船 |

## 三、系统架构与计算平台路线

### 3.1 分层架构

```
┌──────────────────────────────────────────────────────────┐
│  岸基地面站：操作台(摇杆) + 任务规划 + 视频监视 + 数据回放   │
└────┬──────────────────┬──────────────────┬───────────────┘
     │ 控制&遥测         │ RTK 差分(RTCM3)  │ 视频
     │ MAVLink/UDP      │ NTRIP            │ RTSP/WebRTC
┌────┴──────────────────┴──────────────────┴───┐
│  通信层：4G 模组 / 数传电台（主备）             │
└────┬──────────────────────────────────┬──────┘
     │                                  │
┌────▼──────────────────────┐   ┌───────▼────────┐
│ Linux 上位机（非实时）      │   │ 网络摄像机      │
│ 任务管理 / 日志 / 链路管理   │   │ （独立推流）    │
│ NTRIP 客户端 / 参数 / OTA   │   └────────────────┘
│ [预留] 感知与避障           │
└────┬──────────────────────┘
     │ CAN / UART (MAVLink)
┌────▼────────────────────────────────────────────┐
│  实时控制 MCU（硬实时）                            │
│  任务层：航线管理、航点切换、模式状态机             │
│  制导层：LOS 导引 → ψ_d；DP 参考 → η_d             │
│          [预留] 指令仲裁器（避障可覆写）            │
│  控制层：艏向/速度/位置 PID + 环境力前馈            │
│  分配层：(τ_X, τ_Y, τ_N) → 各推进器指令            │
│  导航层：GNSS/INS → (x,y,ψ,u,v,r) @100Hz           │
└────┬────────────────────────────────▲───────────┘
     │ CAN                            │ UART+PPS / RS485
┌────▼──────────────┐   ┌─────────────┴──────────────┐
│ ESC → 推进器 ×N    │   │ GNSS/INS / 测深 / 风速 /    │
└───────────────────┘   │ BMS / 漏水                  │
                        └────────────────────────────┘
```

**三条设计原则**

1. **分层解耦**：更换推进构型只改分配层，控制层以上零改动
2. **实时与非实时分离**：Linux 死机不影响停船，安全逻辑全部在 MCU
3. **预留而不实现**：感知/避障通过仲裁器接入，本期实现为透传

### 3.2 算力测算

| 任务 | 频率 | 运算量 |
|---|---|---|
| 组合导航 ESKF（15 维） | 200 Hz | 约 0.7 MFLOPS（采购 GNSS/INS 一体机时此负载在导航盒内，MCU 只解析） |
| 三自由度 DP 控制 | 100 Hz | < 5 kFLOP/帧 |
| LOS 制导 | 20–50 Hz | < 1 kFLOP/帧 |
| 四推力分配（带约束 QP） | 100 Hz | 约 5 MFLOPS |

**结论**：上述功能一颗 STM32H743（480 MHz，双精度 FPU）总占用可控制在 40% 以内，**不需要 GPU/NPU**。作为对照，视觉目标检测需 10~30 TOPS，差两个数量级——是否配 AI 算力取决于是否纳入感知功能，与本期控制无关。

> **工程简化**：固定角度布置的分配矩阵是常数矩阵，可离线预计算伪逆，在线只做"伪逆 + 饱和处理 + 迭代重分配"，运算量降到 QP 的 1/10，且无求解器不收敛风险。仅在推力饱和时启用完整 QP。**建议默认采用。**

### 3.3 计算平台路线

| 路线 | 组成 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| **纯 MCU** | STM32H7 单板 | 成本最低、最可靠、启动快 | 无日志空间、无视频、难扩展、开发工具链弱 | 功能固定的简单船 |
| **MCU + Linux（推荐）** | STM32H7 + RK3568/RK3588 | 实时性与扩展性兼得；安全逻辑不依赖 Linux | 需设计双核通信与时间同步 | 通用推荐 |
| **Pixhawk + ArduPilot** | 现成飞控 + 开源固件 | 上手最快，遥控/航线开箱可用 | **全驱动锁艏向 DP 支持有限**，需改核心代码；**GPLv3 衍生代码需开源** | 早期验证、船体调试 |
| **纯 Linux 单板** | RK3588 + PREEMPT_RT | 架构简单、算法开发快 | 实时抖动难保证，死机即失控，需外部安全 MCU 兜底 | 研究平台 |

**关于 ArduPilot 的建议用法**：用于第一版硬件联调、推进器验证、快速跑通遥控与基本航线，**但正式版本控制层自研**。理由是全驱动 DP 与降级策略需深度定制，且需规避 GPL 传染性。

**上位机选型权衡**：若确定不纳入视觉感知，RK3568 足够；若需为后续 AI 功能预留，RK3588 自带约 6 TOPS NPU，可支撑轻量检测模型，差价约 1,500 元，远低于后期换板代价。

### 3.5 船上布局与安装约束

```
      艏 ─────────────────────────────────── 艉
   [测深仪]                            [GNSS天线1]
   前视倾斜20~30°                           │
       │      [GNSS天线2]                   │
       │           │ ← 双天线沿中轴线，基线 ≥1.2 m

```

**必须遵守的安装约束**

1. 双天线**沿船中轴线纵向布置**，基线 ≥1.2 m，上方 15° 仰角内无遮挡
2. GNSS 天线远离推进器、电池、大电流线缆 **≥30 cm**（多推进器方案电磁环境更恶劣）
3. GNSS/INS 惯导单元 **靠近重心**，加减振垫隔离推进器振动（一体机内的 IMU 随盒子安装；天线杆臂与盒子安装角分别记录）

6. 电子舱防水 ≥IP67；大功率系统需金属舱壁导热或强制风道
7. 急停开关装在船外可触及处，并支持地面站远程触发
8. **推进器安装角度精度 ±1° 以内并记录**，分配矩阵直接依赖它，建议用工装保证

## 四、环境载荷、推力与能量：计算方法与算例

> 本章是全船设计的定量基础——推进器功率、电池容量、船体尺寸、续航指标全部从这里推导。**船体详细设计确定后必须按实际投影面积复算。**

### 4.1 计算方法

```
风力：  F = 0.5 · ρ_air   · Cd · A · V²      ρ_air   = 1.225 kg/m³
流力：  F = 0.5 · ρ_water · Cd · A · V²      ρ_water = 1000  kg/m³
```

投影面积与阻力系数取值（3.5 m × 1.8 m 双体船算例）：

| 投影 | 面积 | Cd |
|---|---|---|
| 水上正面（迎风） | 1.0 m² | 0.9 |
| 水上侧面（迎风） | 1.8 m² | 1.1 |
| 水下正面（迎流） | 0.20 m² | 0.9 |
| 水下侧面（迎流） | 1.00 m² | 1.2 |

水下侧面按双体船有效遮蔽效应折算，不是两个片体简单相加。

### 4.2 算例

**工况 1：常规环境（风 8 m/s，流 0.5 m/s）**

| 方向 | 风力 | 流力 | 合计 |
|---|---|---|---|
| 纵向（顶风顶流） | 35 N | 23 N | **58 N** |
| 横向（正横受力） | 78 N | 150 N | **228 N** |

**工况 2：设计环境（风 10 m/s，流 0.8 m/s）**

| 方向 | 风力 | 流力 | 合计 |
|---|---|---|---|
| 纵向（顶风顶流） | 55 N | 58 N | **113 N** |
| 横向（正横受力） | 121 N | 384 N | **505 N** |
| 艏摇力矩（力臂取 0.1L=0.35 m） | — | — | 约 **177 N·m** |

### 4.3 关键结论：锁艏向的代价

```
顶流定点（艏向自由）：环境力作用在正面投影
    水下正面 ≈ 0.20 m²  →  流力 58 N（0.8 m/s）

锁定艏向（最恶劣方位，流从正横来）：作用在侧面投影
    水下侧面 ≈ 1.00 m²  →  流力 384 N（0.8 m/s）

                        差 6.6 倍
```

原因是水密度是空气的 800 倍，侧面投影又是正面的约 5 倍。**推力需求相差 4.5 倍，功率需求相差近 10 倍**（功率与推力约成正比，但需同时维持三自由度）。这一条决定了：

- 是否锁艏向直接决定推进器规格、电压等级、电池容量、船体尺寸
- 采用双体船会进一步放大侧向投影，与锁艏向需求相冲突
- 若能在合同中约定"不保证流向与艏向垂直的最恶劣方位"，推进器可小一档

### 4.4 推力选型

```
设计推力需求 = 最大方向环境力 × 安全系数 1.3
             = 505 × 1.3 = 657 N
（安全系数覆盖阵风、涌浪、控制动态余量、Cd 估算误差）

四推 ±45° 产生纯横向力时：
    F_Y,max = 4 · F_single · sin45° = 2.83 · F_single
    F_single ≥ 657 / 2.83 = 232 N ≈ 23.7 kgf

同时需产生 177 N·m 艏摇力矩，占约 20% 推力裕度
    → 单机额定推力 ≥ 30 kgf
```

**选型结论（算例）**：4 台 × 30 kgf 级无刷水下推进器，桨径 φ150~180 mm，48V。
作为对照，同尺度**欠驱动方案**（不锁艏向、顶流定点）仅需 2 台 × 15 kgf、24V。

**必须校核的三点**

1. **倒车推力**：正反转推力不对称，倒车通常仅正车 60~70%，选型按反转推力校核
2. **浅浸没吸气（Ventilation）**：桨轴中心宜在水线下 ≥1.5 倍桨径处。浅吃水时此条常与桨径冲突，需通过"片体最低点安装"或"小直径高转速桨"解决，**详细设计阶段必须专项验证**
3. **水草缠绕**：推进器数量越多风险越高，建议加导流罩或防缠绕格栅

### 4.5 功率与电池

推力功率比按工业级水下推进器典型值 **0.15 N/W**（1 N 推力约需 6.7 W）估算：

| 工况 | 所需推力 | 推进功率 | 电控/传感/通信 | 总功率 |
|---|---|---|---|---|
| 1.5 m/s 巡航 | 约 50 N（船体阻力） | 335 W | 75 W | **410 W** |
| 顶流定点（常规环境） | 58 N | 387 W | 75 W | **460 W** |
| 锁艏向定点（常规环境，正横） | 228 N | 1,520 W | 75 W | **1,595 W** |
| 锁艏向定点（设计环境，正横） | 505 N | 3,367 W | 75 W | **3,442 W** |

**电池容量推导**

```
按 8 h 巡航：3,280 Wh ÷ DOD 0.8 = 4,100 Wh
选型：48V / 90Ah LiFePO4 ≈ 4,320 Wh，约 40 kg

选 48V 而非 24V：四推 30 kgf 峰值总电流在 24V 下可达 400 A+，
线损与线径不可接受；48V 电流减半，且多数大功率推进器原生支持
```

### 4.6 续航必须按工况分别定义

| 工况 | 功率 | 4.32 kWh 可用 80% 时的续航 |
|---|---|---|
| 1.5 m/s 巡航 | 410 W | **8.4 h** |
| 顶流定点 | 460 W | 7.5 h |
| 锁艏向定点（常规环境） | 1,595 W | **2.2 h** |
| 锁艏向定点（设计环境） | 3,442 W | 1.0 h |

**推荐的续航条款写法**

> 续航 ≥8 小时，测试工况为 1.5 m/s 巡航、常规环境（风 ≤8 m/s、流 ≤0.5 m/s）；
> 锁艏向定点作业时长单独约定，常规环境下不低于 1.5 小时。

**混合任务示例**

```
6 h 巡航 + 1 h 锁艏向定点 + 0.5 h 机动余量
= 410×6 + 1595×1 + 800×0.5 = 4,455 Wh
→ 超出 4.32 kWh 的 80% 可用容量，需上浮至约 5 kWh（约 46 kg）
```

> **单一"小时数"无法定义续航**，必须以任务剖面（巡航/定点时长配比）表述。这是最容易产生验收争议的条款。

## 五、传感器选型

### 5.1 选型总原则

1. 按"核心导航一套 + 安全一套 + 遥控视野一套"配置，不按功能重复堆硬件
2. 状态量能否可靠获得，决定功能能否实现——**传感器等级不足时算法无法补救**
3. 每个传感器都要设计失效后的降级路径，没有降级路径的传感器不能进入闭环
4. 传感器精度与差分链路冗余度**耦合选择**（见 5.4）
5. 核心导航按 **GNSS/INS 组合导航**采购，不要单独买裸 IMU 再现场拼融合；电机转速与舵角/吊舱转角**不进惯导解**（见 5.5）

### 5.2 航向测量路线（最容易选错的一项）

艏向 ψ 是定点锁艏、定向巡航、航线跟踪的共同基础。可选路线：

| 路线 | 原理 | 精度 | 致命缺陷 | 结论 |
|---|---|---|---|---|
| **磁罗盘 / 电子罗盘** | 地磁场 | 静态 1~2° | **船上基本废掉**：电机与大电流线缆磁场随油门变化，航向可漂十几度，且是随工况变化的动态误差，标定无效 | 不作主航向源 |
| **单天线 GNSS 反推（COG）** | 由地速方向反推 | 动态 1~3° | 零速时完全不可信；COG 是**航迹方向不是船头方向**，横流下可差 20° 以上 | 仅可作巡航时的辅助校验 |
| **双天线 RTK 基线** | 两天线相位差解算基线矢量 | **约 0.2°/m 基线**（1.2 m 基线 ≈ 0.17°） | 依赖卫星可见性与差分质量 | **推荐主方案** |
| **光纤陀螺（FOG）** | 惯性 | 短期极优 | 需初始对准，长期漂移需外部修正，成本高（数万起） | 与 GNSS 组合时可选 |
| **双天线 GNSS/INS** | RTK 基线航向 + IMU 捷联融合 | 0.1~0.2°，100 Hz 输出 | 融合黑盒（采购一体机时） | **最终推荐形态** |

> **关键判断**：定点锁艏向恰恰是 COG 与磁罗盘**同时失效**的场景（零速 + 强磁干扰）。**若功能清单中包含定点锁艏向或高精度定向，双天线 RTK 是唯一可靠解**，基线 ≥1.2 m。双天线基线航向作为 GNSS/INS 的标准量测进入组合解；磁航向、电机转速、舵角都**不能**替代它。

### 5.3 定位与差分路线

| 路线 | 精度 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|
| 单频 GNSS | 2~5 m | 最便宜 | 无法做米级以下定点与贴线 | 仅航线粗巡 |
| **RTK + 自建基站** | 1~2 cm | **不依赖公网**，链路自主可控，延迟低 | 需人工架站、需已知点或自标定、有作用距离限制（通常 <10~20 km） | 固定作业区、无公网覆盖 |
| **RTK + 网络 CORS（NTRIP）** | 1~2 cm | 无需架站，覆盖广 | **依赖 4G 与服务商，无本地备份**，服务年费 | 有稳定公网覆盖 |
| 双服务商 + 双运营商网络 RTK | 1~2 cm | 冗余度高 | 成本上升，仍受公网整体故障影响 | 公网方案的推荐形态 |
| RTK + 高精度 GNSS/INS | 短时中断可维持 | 抗遮挡与短时失锁 | 一体机内 IMU 成本上升 | **与上述任一差分路线叠加，不是替代差分** |

> **两条路线的实质区别**：自建基站给的是**链路自主性**，网络 RTK 给的是**部署便利性**。**若不允许自建基站，缺失的本地冗余必须由 GNSS/INS 内部更高等级的 IMU 来补**——这是 5.4 的直接由来。不要用桨转速或舵角去「补」失锁，那不是惯性保持。

### 5.4 惯导器件等级如何选（GNSS/INS 内部的 IMU，与差分冗余耦合）

IMU 是陀螺+加计器件，INS 是对其积分得到位置/速度/姿态的系统，GNSS/INS 是 GNSS 修正后的组合导航。本方案采购的是 **GNSS/INS 一体机**；下表选的是**盒子里面那颗 IMU 的等级**，不是再外挂一颗消费级模块。

差分中断期间，位置精度由该 IMU 的惯性保持能力决定：

| IMU 等级 | 陀螺零偏稳定性 | 断差分 60 s 后 | 大致价格 | 适用 |
|---|---|---|---|---|
| 消费级 MEMS | 50~500 °/h | 位置漂移 >10 m | 数百元 | 不可用于本类闭环 |
| 工业级 MEMS | < 10 °/h | 航向漂 约 0.17°，位置漂移**可达数米** | 3,000~15,000 | 有基站冗余时可用 |
| **高精度 MEMS / 低端战术级** | **< 1 °/h** | 航向漂 约 0.017°，位置漂移**可控制在 1 m 内** | 15,000~45,000 | **无本地差分冗余时必需** |
| 战术级 FOG | < 0.1 °/h | 可维持数分钟 | 5 万以上 | 长时间失锁场景 |

**选型规则**

```
有自建基站（本地差分冗余）+ 允许短时精度下降  →  工业级 MEMS < 10 °/h
仅网络 RTK（无本地冗余）                     →  高精度 < 1 °/h（增量约 1.5~3 万）
长隧道/桥下/岸壁遮挡作业                     →  考虑 FOG 或加 DVL
```

> 这条因果关系建议明确告知客户：**"不允许自建基站"这一条约束的代价，会以 GNSS/INS 内 IMU 升级的形式出现在成本里。**

### 5.5 必选传感器清单与导航采购形态

**先分清三个词，避免采购和接线接错**

| 名称 | 实际是什么 | 输出 | 本方案怎么用 |
|---|---|---|---|
| **IMU** | 陀螺 + 加计，惯性器件 | 三轴角速度、三轴加速度 | GNSS/INS **内部**器件；等级按 5.4 选，默认不单独外购 |
| **INS** | IMU + 捷联积分 | 位置、速度、姿态（无外部修正会漂） | 不单独采购纯 INS |
| **GNSS/INS** | 双天线 RTK + IMU + 组合解算 | 位置、对地速度、姿态/艏向，约 100 Hz | **推荐采购形态**：组合导航一体机 |

**推荐采购形态**：双天线 RTK + 按 5.4 选定等级的 IMU + 内置组合解算，做成 **GNSS/INS 组合导航一体机**，直接输出 `(x, y, ψ, u, v, r)`。可省 1~2 个月融合开发，精度有厂商保证；代价是融合过程黑盒、参数调整受限。若团队有惯导积累且需深度定制，可自研 ESKF（见 7.4）——**仅在自研时**才拆成「双天线板卡 + 独立 IMU」。

| 传感器 | 参考档次 | 输出数据 | 频率 | 精度要求 |
|---|---|---|---|---|
| **GNSS/INS 组合导航** | 双天线 RTK 一体机（如和芯星通/Septentrio 等方案）；内部 IMU 按 5.4 | 经纬高、ENU 对地速度、姿态/艏向、解状态、卫星数、PDOP、差分龄期；内部仍有角速度/加速度 | 导航解 50–200 Hz；GNSS 原始 5–20 Hz | 平面 1 cm+1 ppm（FIX）；航向 0.2°/m 基线；IMU 见 5.4 |
| **电机转速/电流反馈** | CAN 电调内置 | 转速、电流、温度、故障码 | 20–50 Hz | ±1%；**进推力观测与故障诊断，不进 GNSS/INS** |
| **舵角 / 吊舱转角**（仅路线 A/E） | 舵机编码器或吊舱反馈 | 实际转角 | ≥20 Hz | 进推力分配与执行器闭环，**不进 GNSS/INS** |
| **电池 BMS** | 系统配套 | 电压、电流、SOC、单体温度 | 1–5 Hz | — |

> 四推矢量固定布置（路线 D）没有活动舵角：安装角是常量，标定后写入分配矩阵即可。

**哪些量进 GNSS/INS，哪些量不进（禁止照搬汽车 INS）**

汽车 GNSS/INS 常接轮速脉冲和方向盘转角做里程计辅助。水面船**不得**把这套接口接到船上——转速反映对水负荷，有流时不等于对地速度；舵角是执行器状态，并不唯一决定艏向 `ψ` 或转艏角速度 `r`。

| 数据 | 是否进入 GNSS/INS 滤波器 | 原因与去处 |
|---|---|---|
| 双天线 RTK 位置、多普勒测速 | **进入** | 对地位置与速度，定点/航线的主量测 |
| 双天线基线航向 | **进入** | 零速仍可用的船头朝向；INS 的标准航向量测 |
| IMU 角速度、加速度 | **进入**（内部捷联） | 高频姿态与短时推算 |
| 磁罗盘航向 | **不进入** | 船上磁场随油门变化，见 5.2 |
| 电机转速 / 电流 | **不进入** | 有流时 ≠ 对地速度；当速度观测会把导航解带偏。正确去处见 7.5 |
| 舵角 / 吊舱转角 | **不进入** | 不唯一决定 `ψ`、`r`；船有侧漂与环境力矩。正确去处见 8.0 |
| 电调转速接到厂商「轮速 / 里程计」口 | **禁止** | 车规功能；船上接了会在有流时把定点做坏 |

转速、电流的正确用法：反推实际推力，与加速度一起做「期望推力 − 实际推力 − 加速度响应」，服务环境力估计和堵转检测（7.5）。舵角/吊舱转角的正确用法：推力分配与执行器闭环（8.0）。

水面短时 GNSS 失锁靠 5.4 的 IMU 等级撑住，或以后加 DVL；**不要用桨转速冒充里程计。**

### 5.6 安全与实用必备

| 传感器 | 输出 | 频率 | 用途 |
|---|---|---|---|
| **测深方案**（见 5.7） | 水深 | 1–10 Hz | 防搁浅 |
| **风速风向仪** | 相对风速、风向 | 1–10 Hz | **DP 环境力前馈**；锁艏向定点时尤为关键 |
| **漏水传感器 + 舱内温湿度** | 开关量/模拟量 | 1 Hz | 进水立即停车报警返航 |
| **网络摄像机（前视，云台可选）** | H.264/H.265 | 25–30 fps | **遥控操作员视野** |

> 摄像机在无自主避障的方案中是**功能组成部分而非附件**——它是"有人值守替代自主避障"这一设计成立的前提。视频独立推流，不进控制闭环，不占船载算力。

### 5.7 浅水测深专项

**问题本质**：常规单波束测深仪换能器正下方存在 **0.3~0.5 m 盲区**，在最浅处恰好读不到数；且"测到浅水时船已经在浅水上"，没有反应距离。

| 层级 | 手段 | 说明 |
|---|---|---|
| **第一层：先验水深图** | 作业前测绘水域生成栅格水深图，浅于阈值区域设为**禁航区**（地理围栏） | 固定湖泊/港区场景下**最可靠**，把安全问题在规划阶段解决 |
| **第二层：低盲区测深仪** | 200 kHz 以上高频浅水测深仪，盲区可降至 0.15 m | 实时兜底 |
| **第三层：前视倾斜探测** | 换能器**向前下方倾斜 20~30°**，探测船前 2~3 m 水深 | 解决"反应距离"问题 |
| 备选：前视声呐 / 测扫声呐 | 探测范围大 | 成本高、数据处理复杂、浅水多路径严重 |

**推荐组合：第一层 + 第三层**（第二层作为第三层的实现方式）。

**保护逻辑（阈值按吃水与船速标定）**

```
水深 < 0.8 m               →  限速 0.5 m/s + 报警
水深 < 0.6 m               →  停车 + 强制原路后退
水深 < 0.5 m 或 数据无效超时 →  停车 + 报警 + 等待人工接管
```

### 5.8 可选与预留

| 设备 | 说明 |
|---|---|
| **DVL 多普勒计程仪** | 直接测对地三轴速度（含横向 v），DP 精度可再上一档；但数万元起，且**有最小水深限制（通常 0.3~1 m）**，浅水场景可能不可用 |
| 电磁计程仪 | 测对水速度 STW，用于评估推进器负载与水流估计 |
| 水质多参数探头等 | 属作业载荷范畴，需明确供电与数据接口 |
| 毫米波雷达 / 激光雷达 | 自主避障用。预留桅杆安装位（视野无遮挡）、12V/30W、以太网或 CAN |
| 靠泊用激光测距 / 视觉 | 预留舷侧安装位、供电、网口 |
| AIS 接收机 | 预留天线位（与数传天线间距 ≥1 m 避免互扰）、UART |
| AI 计算模块 | 预留 100×80 mm 空间、12V/60W、散热风道、千兆网口 |

## 六、通信架构

### 6.1 三条独立数据流

| 数据流 | 带宽 | 延迟要求 | 可靠性 | 承载建议 |
|---|---|---|---|---|
| 控制 + 遥测 | 5~50 kbps | **< 200 ms** | 高 | 4G UDP + 数传电台 |
| RTK 差分 | 1~5 kbps | < 2 s（差分龄期） | 高 | 4G NTRIP 或电台转发 |
| 视频 | 1~4 Mbps | < 500 ms | 低（可丢帧） | 4G RTSP/WebRTC |

> **关键设计**：视频必须走独立通道或 QoS 低优先级，**绝不能因视频拥塞影响控制指令**。

### 6.2 链路路线对比

| 路线 | 距离 | 延迟 | 优点 | 缺点 | 适用 |
|---|---|---|---|---|---|
| **数传电台（900M/1.4G）** | 3~10 km（视距） | 低（<50 ms） | 不依赖运营商、延迟稳定、成本低 | 带宽小（不能传视频）、需视距、需频率合规 | 无公网水域、作为备份链路 |
| **图数一体电台** | 3~10 km | 中 | 可传视频、自组网 | 成本高、功耗大、仍需视距 | 无公网 + 需视频 |
| **单 4G/5G** | 覆盖范围内 | 100~300 ms | 带宽大、部署简单 | 依赖运营商，湖区常有盲区 | 有稳定覆盖 |
| **双 4G（双运营商）** | 同上 | 同上 | 覆盖互补、故障切换 | 成本与配置复杂度上升 | **公网方案推荐形态** |
| Wi-Fi Mesh | <1 km | 低 | 带宽大、成本低 | 距离短、抗干扰差 | 小水域、近岸 |
| 卫星（北斗短报文/天通） | 全域 | 秒级 | 无覆盖依赖 | 带宽极小、延迟大 | 仅作最后生命线 |

**推荐组合**：**双 4G（主，含视频）+ 数传电台（备，仅控制与遥测）**。电台作为"公网全断时把船开回来"的兜底手段，这条链路的存在价值远高于其成本。

### 6.3 协议与消息

**协议：MAVLink v2**（成熟、有校验与序号、地面站生态现成）。

| 方向 | 消息 | 频率 | 内容 |
|---|---|---|---|
| 上行 | `MANUAL_CONTROL` | 10~20 Hz | 摇杆量（全驱动为三自由度） |
| 上行 | `SET_MODE` | 事件 | MANUAL / DP / HEADING / SPEED / AUTO / RTL |
| 上行 | `SET_POSITION_TARGET` | 事件 | 定点目标经纬度 + 目标艏向 |
| 上行 | `MISSION_ITEM` | 上传时 | 航点表 |
| 上行 | `PARAM_SET` | 调试 | 在线改 PID |
| 上行 | `COMMAND_LONG(EMERGENCY_STOP)` | 事件 | 急停 |
| 双向 | `HEARTBEAT` | 1 Hz | 链路存活判定 |
| 下行 | `GLOBAL_POSITION_INT` | 5~10 Hz | 经纬度、地速、艏向 |
| 下行 | `ATTITUDE` | 10 Hz | 姿态与角速度 |
| 下行 | `GPS_RAW_INT` | 2 Hz | 解状态、卫星数、PDOP、**差分龄期** |
| 下行 | `SYS_STATUS` / `BATTERY_STATUS` | 1 Hz | 电压、电流、SOC、故障位 |
| 下行 | `ESC_STATUS` | 5 Hz | 各推进器转速、电流、温度 |
| 下行 | `NAV_CONTROLLER_OUTPUT` | 5 Hz | 跨航迹误差、目标艏向、目标速度 |
| 下行 | 自定义 `DP_STATUS` | 5 Hz | **位置误差、艏向误差、降级等级、推力饱和度** |
| 下行 | `STATUSTEXT` | 事件 | 报警与提示 |

> `DP_STATUS` 是定点功能的核心态势信息：操作员必须实时看到"现在还锁不锁得住、推力用了几成"。

### 6.4 可靠性设计

- **指令序号 + 时间戳**：船端丢弃比已执行指令更旧的包，防 UDP 乱序
- **心跳超时**：连续 3 s 无心跳判定失联，触发 9.2 分级保护
- **摇杆包超时归零**：>500 ms 未收到新摇杆量**自动归零**，而非保持最后值
- **链路质量监测与滞回切换**：主链路丢包 >20% 持续 2 s 切备；备链路稳定 10 s 且主恢复才切回。**必须有滞回**，否则临界点反复抖动

### 6.5 RTK 差分链路

```
GNSS/INS 模块 ←RTCM3← 上位机 NTRIP 客户端 ←┬─ 4G-A（运营商1）→ 服务商 A
      └─ 上报 GGA（供 VRS 解算）           └─ 4G-B（运营商2）→ 服务商 B
```

**网络 RTK 方案的四重冗余**（用于弥补无本地基站）

| 措施 | 说明 |
|---|---|
| 双运营商 4G | 湖区/港区常有单一运营商盲区 |
| 双 NTRIP 服务商账号 | 服务端故障时自动切挂载点 |
| 断线指数退避重连 | 重连期间保持惯导推算 |
| GNSS/INS 惯性保持 | 内部 IMU 等级见 5.4；**不靠桨转速推算位置** |

**差分状态与模式准入**

```
差分龄期 < 2 s 且 RTK FIX  →  全模式可用
差分龄期 2~5 s             →  提示，模式保持
差分龄期 > 5 s 或 FLOAT    →  禁止切入精密定点；已在定点则降级
无差分 / 单点定位           →  见 7.3 降级表
```

> **这套判断逻辑必须做进地面站 UI**：不满足条件的模式按钮直接置灰，从源头杜绝误操作。

## 七、数据处理：从原始读数到可用状态

> 传感器不是插上就能用。这一层做不好，后面控制算法调到死也没用，**工作量往往占整个导航系统的 70%**。采购 GNSS/INS 一体机可省掉 7.4 的融合工作，但 7.1~7.3 的标定、时间同步和故障处理仍必须自己做。转速与舵角的预处理在控制/分配层完成，**不要送进组合导航滤波器**。

### 7.1 坐标系与时间基准

**坐标系**

- **WGS-84**：GNSS 原始输出
- **本地 NED 平面**：以任务起点或首个 FIX 点为原点，转为米制 `(x_北, y_东)`，**所有控制运算在此进行**
- **船体系 BODY**：原点在重心，x 指船首、y 指右舷、z 向下

湖泊/港区尺度 <10 km 时等距投影近似即可：

```
x_北 = (φ − φ0) · R_M
y_东 = (λ − λ0) · R_N · cos(φ0)
```

**时间同步（最易忽视也最致命）**

- 以 **GNSS 的 PPS 秒脉冲**作为全系统时间基准；GNSS/INS 内部 IMU 采样由一体机打硬件时间戳，自研时 IMU 必须同样打戳
- 所有数据带 timestamp，融合时**按时间戳对齐，不能按到达顺序处理**
- GNSS 有 20~100 ms 固有延迟，必须实测并做**量测延迟补偿**（缓存历史状态，回溯更新）
- 上位机与 MCU 之间同样要同步（MCU 为主时钟）
- **典型故障**：不做时间同步 → 转弯时位置估计"甩尾" → 航线跟踪规律性超调，PID 怎么调都调不好

### 7.2 标定项

| # | 标定项 | 方法 | 不做的后果 |
|---|---|---|---|
| 1 | **GNSS 杆臂**  `p_船 = p_天线 − R(φ,θ,ψ)·l` | 卷尺量准到 cm | 转弯时位置"画圈" |
| 2 | **双天线安装偏角** ψ_offset | 直线满速航行时比对双天线航向与 COG 稳态差 | 艏向整体偏一截 |
| 3 | **GNSS/INS 安装误差角** | 静止 + 匀速直线两组数据 | 加速度投影错、速度漂移 |
| 4 | **陀螺零偏** | 每次上电静止 10~30 s 估计（船必须停稳） | 航向慢漂 |
| 5 | **推力标定曲线** | 系泊状态测"指令→转速→推力"，**正反转分别标定** | 前馈失效；倒车推力只有正车 60~70% |
| 6 | **推进器安装角度** | 系泊试验中单推加载 + 测力/测响应反推 | **±3° 误差即产生明显运动耦合**（想横移却带转艏） |
| 7 | **舵角/吊舱转角零位**（仅路线 A/E） | 机械中位对齐船体纵轴，编码器对零 | 分配方向整体偏转；**此标定只服务分配层，结果不写入 GNSS/INS** |

### 7.3 预处理与降级策略

```
原始数据 → 时间戳对齐 → 有效性检查 → 野值剔除 → 滤波 → 融合（GNSS/INS 内部或自研 ESKF）
```

- **有效性检查**：GNSS 解状态、卫星数 ≥6、PDOP <3、差分龄期 <5 s；GNSS/INS 量程与死机检测；数据超时（GNSS 连续 1 s 无新数据即失效）
- **野值剔除**：新息卡方检验，超 3σ 拒绝该帧量测（比固定阈值鲁棒，能自适应工况）
- **分层**：位置/速度/姿态只走 GNSS/INS；转速/电流/转角走控制与分配，两路不要在融合步骤混在一起

**GNSS 状态 → 允许的模式**

| GNSS 状态 | 定位精度 | 允许的模式 |
|---|---|---|
| RTK FIX | 1–2 cm | **全部模式，含精密定点** |
| RTK FLOAT | 10–50 cm | 定点精度放宽一档、航线放宽容差 |
| 单点定位 | 1–3 m | 遥控、定向、定速；**禁止精密定点** |
| 失锁 <60 s | 依 GNSS/INS 内 IMU 等级（见 5.4） | 短时维持定点，持续报警 |
| 失锁 >60 s | 不可用 | 停车 → 报警 → 等待接管 |

### 7.4 组合导航：自研 vs 采购

采购对象是 **GNSS/INS 一体机**（双天线 RTK + 内部 IMU + 厂商融合），不是裸 IMU。自研时 IMU 只作为 ESKF 的预测传感器。

| 路线 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **采购 GNSS/INS 一体机** | 省 1~2 个月、精度有保证、厂商支持 | 融合过程黑盒、参数受限、单价高 | 周期紧、非差异化环节 |
| **自研 ESKF** | 可深度定制（延迟补偿、多源融合、自定义降级） | 开发与调试周期长，精度依赖工程能力 | 有惯导积累、需长期迭代 |

**自研时的 15 维误差状态 ESKF**

```
δx = [ δp(3)  δv(3)  δθ(3)  δb_g(3)  δb_a(3) ]ᵀ

预测 @200 Hz：IMU 捷联递推，更新标称状态与协方差
更新 @10 Hz ：RTK 位置（杆臂补偿后）、GNSS 多普勒测速、双天线基线航向
误差注入与重置
输出 (x, y, ψ, u, v, r) @100~200 Hz
```

**滤波器量测清单（自研与采购一体机同一原则，见 5.5）**

- **进入更新**：RTK 位置、GNSS 多普勒测速、双天线基线航向
- **不进入更新**：电机转速/电流、舵角/吊舱转角、磁航向
- 若一体机提供「轮速 / 里程计 / 外部航向」接口：双天线通常已内置，**不要接电调转速或舵角**

**横漂速度 v 的获取**：无 DVL 时由 GNSS 地速在船体系分解

```
[u, v]ᵀ = R(ψ)ᵀ · [V_北, V_东]ᵀ
```

得到的是**对地速度**（含水流影响），这正是 DP 需要的——定点做的是对地控制。**锁艏向定点时 v 是横向位置环的关键阻尼项**（欠驱动方案中它只是旁观量），对其噪声水平的要求显著更高。用电机转速反推的是对水效应，不能代替这里的 `u, v`。

### 7.5 环境干扰估计

风、流、浪合力建模为缓变未知常值力，用扩展状态观测器或在滤波器中加 bias 状态在线估计：

```
状态扩展：b = [b_X, b_Y, b_N]ᵀ,   ḃ = 0 + w
```

估计结果**作为前馈直接抵消**。

- 定点时环境力可达数百牛，若完全靠 PID 积分去"憋"，积分饱和、响应迟滞、超调都会很严重
- 加前馈后 PID 只处理残差与动态部分，**定位精度和抗扰速度有质的提升**
- **风速仪数据作为额外量测源**，让风载荷估计更快收敛（风变化快，纯观测器跟不上）
- **电调回传的转速/电流反推实际推力，作为本观测器的输入，不要送进 GNSS/INS**：形成「期望推力 − 实际推力 − 加速度响应」闭环校验，可显著提高环境力估计准确度，并用于堵转/缠绕检测。转速在此层的身份是推力计，不是速度计

## 八、控制策略：逐条实现五种模式

### 8.0 底层：推力分配（按构型分）

**欠驱动（双桨差速）**

```
F_左 = (τ_X − τ_N·2/b) / 2
F_右 = (τ_X + τ_N·2/b) / 2
τ_Y 无法产生 → 制导层必须把横向需求转化为艏向需求（侧偏角）
```

**全驱动（四推矢量）**

```
第一级（常规，占 95% 以上时间）：
    F = T⁺ · τ        T⁺ 为离线预计算的伪逆矩阵（常数）
    运算量极小，无收敛风险

第二级（推力饱和时启用）：
    带约束 QP：min ‖F‖²  s.t.  T·F = τ,  F_min ≤ F ≤ F_max
    若无可行解，按优先级松弛
```

**必须处理的四件事**

1. **饱和优先级**：明确"保什么、放什么"。若锁艏向是核心指标则 **艏向 > 横向位置 > 纵向位置**；若定点精度优先则相反。此优先级与 8.2 降级策略联动
2. **速率限幅**：限制推力变化率，保护电调与机械，避免抖动
3. **反向死区补偿**：正反转推力不对称，零点附近有死区，用 7.2 标定曲线做反向映射
4. **内力最小化**：冗余构型会产生互相抵消的推力分量，白白耗电。伪逆解天然是最小二范数解已隐含此优化，但饱和重分配时须避免引入额外内力

**双方位吊舱（路线 E）**：推力分配用「转速/推力 + 实际转角」。转角反馈只进入本层与舵机闭环，**不作为航向量测、不进 GNSS/INS**。转角速率限制造成的动态滞后在分配层用速率约束处理，不要靠惯导去「猜」舵还没转到的角度。

### 8.1 远程控制（前后左右）

**Level 1 — 直通模式（必须保留的兜底）**

```
τ_X = k1 · 左摇杆纵向      （前进/后退）
τ_Y = k2 · 左摇杆横向      （左右平移，仅全驱动可用）
τ_N = k3 · 右摇杆横向      （左转/右转）
```

开环给推力，延迟最低、逻辑最简单。**导航或链路异常时靠它把船开回来。**

**Level 2 — 速度闭环（推荐默认）**

```
u_d = 左摇杆纵向 · u_max  →  纵向速度 PID  →  τ_X
v_d = 左摇杆横向 · v_max  →  横向速度 PID  →  τ_Y   （全驱动）
r_d = 右摇杆横向 · r_max  →  角速度 PID    →  τ_N
```

摇杆量映射成期望速度而非推力，顺流逆流手感一致，新手也能开。

**Level 3 — 松杆保持**

摇杆回中自动切入定点保持（锁住松杆瞬间的位置与艏向）。全驱动构型下体验极佳，是产品亮点。

> **"前后左右"的构型差异**：全驱动可实现**真正的左右平移**（船头不变的侧移）；欠驱动的"左右"实际是"转弯前进"，与操作员直觉不符。若该体验是卖点，需在构型阶段就确定（见第二章）。

**配套安全机制**：失联分级保护（9.2）、摇杆包超时归零、指令序号防乱序、地理围栏、双链路冗余。

### 8.2 定点稳泊

#### 8.2.1 路线一：顶流定点（艏向自由，欠驱动可用）

```
1. 由环境力观测器或位置误差趋势估计环境合力方向 χ_env
2. ψ_d = χ_env（船头顶向环境力来向）
3. 纵向推力维持位置：τ_X = PID(沿艏向的位置误差) + 前馈
4. 横向位置误差通过缓慢调整 ψ_d 消除（船头微偏，用纵向推力斜向拉回）
```

- **优点**：推力需求最小（作用在正面投影）、能耗最低、欠驱动即可实现
- **缺点**：船头随环境摆动；环境力方向变化时有过渡过程；横向误差收敛慢
- **典型精度**：RTK FIX 下 ±0.5~1 m，艏向不可控
- **适用**：采样、监测、等待等不关心船头指向的作业

#### 8.2.2 路线二：三自由度 DP（锁艏向，需全驱动）

```
τ = K_p · R(ψ)ᵀ(η_d − η) + K_d · (−ν) + τ̂_env
     ↑ 误差转到船体系            ↑ 阻尼    ↑ 环境力前馈（7.5）

展开：
  τ_X = k_px · e_x^body + k_dx · (−u) + b̂_X
  τ_Y = k_py · e_y^body + k_dy · (−v) + b̂_Y
  τ_N = k_pψ · wrap_to_pi(ψ_d − ψ) + k_dψ · (−r) + b̂_N
```

**四个关键设计点**

1. **环境力前馈是主力，PID 是配角**。定点时环境力可达数百牛，前馈承担绝大部分，PID 只处理残差与动态。**没有前馈的纯 PID 方案在中等以上风流条件下无法达标**
2. **死区与迟滞**：位置误差 <0.1 m、艏向误差 <1° 时进入保持态，减小推力输出，避免极限环振荡（多台推进器持续微调既耗电又噪声大）
3. **积分项谨慎使用**：前馈已处理常值干扰，积分应设小增益并严格抗饱和，否则与前馈"抢功"导致振荡
4. **推力饱和上报**：实时计算 `‖F‖/F_max`，通过 `DP_STATUS` 上报，让操作员知道还剩多少余量

#### 8.2.3 艏向/位置优先级降级策略

锁艏向时侧向环境力可达纵向的 4~7 倍（4.3 节），必须设计在能力边界处的平滑退化，而不是硬撑到饱和然后失控：

| 等级 | 触发（推力利用率） | 行为 | 地面站 |
|---|---|---|---|
| **L0 正常** | < 60% | 位置 + 艏向同时锁定 | 绿色 |
| **L1 艏向让步** | 60%~85% | 位置优先，艏向容差放宽（如 ±30°），向减小受力方向偏转 | 黄色"艏向精度降级" |
| **L2 顶流保位** | > 85% 持续 10 s | 放弃艏向锁定，转 8.2.1 顶流模式（推力需求降至约 1/5） | 橙色"已放弃艏向锁定" |
| **L3 放弃定点** | 超出设计环境 | 报警 + 自动返航 | 红色"环境超限，返航" |

**降级必须带迟滞**（如 L1→L0 需利用率降到 50% 以下持续 15 s），否则会在阈值附近反复跳变。

> **降级的物理意义**：L2 把船从"横着顶 505 N"变成"顶着 113 N"，推力需求降 4.5 倍、功耗降近 10 倍。这既是安全措施，也是续航保护措施。**此逻辑是否可接受需与客户明确确认**（见第十五章）。

#### 8.2.4 性能预期

| 工况 | 位置精度 | 艏向精度 |
|---|---|---|
| 静水，RTK FIX，全驱动 | ±0.2 m | ±2° |
| 常规环境（风 8/流 0.5），RTK FIX，全驱动 | ±0.5 m | ±5° |
| 设计环境（风 10/流 0.8），RTK FIX，全驱动 | ±0.8 m | ±10°（可能触发 L1） |
| RTK FLOAT | ±1 m | ±5° |
| 常规环境，欠驱动顶流定点 | ±0.5~1 m | 不可控 |

### 8.3 定速巡航

被控量是纵向速度 `u`。

**先确定口径：对地速度（SOG）还是对水速度（STW）？** 默认对地（"定速"通常指对地），**必须在验收指标中写明**。对水速度需电磁计程仪，反映推进器负载，用途不同。

```
τ_X = τ_ff(u_d) + K_p·e_u + K_i·∫e_u dt + K_d·ė_u
      ↑ 来自 7.2 的推力标定曲线
```

- **前馈是关键**：从标定曲线查"跑 2 m/s 需要多少推力"，PID 只补残差，增益可调得温和，超调小、抗扰快
- **不要用电机转速当定速反馈**：转速是对水负荷，有流时与对地速度对不齐。定速环必须用 GNSS/INS 给出的 `u`
- **抗积分饱和**：饱和时冻结积分（Clamping）或反计算（Back-calculation）
- **加速度限幅**：`u_d` 经斜坡限幅再进 PID，避免摇杆猛推导致电流冲击
- **微分用测量微分而非误差微分**，避免设定值突变时的微分冲击
- **全驱动附加**：巡航时四推协同产生纯纵向力，同时用 `τ_Y`、`τ_N` 抑制横漂与偏航，直航稳定性优于差速构型

### 8.4 定向巡航

被控量是艏向角 `ψ`，采用**串级结构**：

```
外环（艏向环，20–50 Hz）：
    e_ψ = wrap_to_pi(ψ_d − ψ)          ← 必须做 ±180° 归一化
    r_d = sat(K_p_ψ · e_ψ, ±r_max)

内环（角速度环，50–100 Hz）：
    e_r = r_d − r
    τ_N = K_p_r · e_r + K_i_r · ∫e_r dt + K_d_r · ė_r
```

**四个必须注意的细节**

1. **角度归一化**：179° 转到 −179° 的误差是 **2°** 不是 **358°**。不做 `wrap_to_pi`，船会在正北掉头时疯狂打转
2. **`r_max` 限幅**：如 30°/s，保护设备也让航行平稳
3. **增益随速度调度**：低速时水动力阻尼小，同样力矩转艏效果更强
4. **积分冻结**：推力饱和或大角度转向时冻结积分

### 8.5 按航线巡航

结构 = **任务层（航点管理）+ 制导层（LOS）+ 8.3/8.4 的速度环与航向环**。

**航线定义**

```json
{
  "mission_id": "lake_patrol_01",
  "loop": true,
  "waypoints": [
    {"id": 1, "lat": 30.123456, "lon": 120.654321,
     "speed": 2.0, "accept_radius": 3.0, "action": "none"},
    {"id": 2, "lat": 30.124000, "lon": 120.655000,
     "speed": 1.0, "accept_radius": 2.0, "action": "hold_60s",
     "hold_heading": 90.0}
  ]
}
```

`hold_heading` 用于"到点后锁艏向悬停"，仅全驱动构型可执行。

**制导算法：LOS 视距导引**

核心思想：不要让船"追航点"（会切角、超调、绕圈），而要"贴着两航点之间的连线走"。

```
路径段：P_k(x_k,y_k) → P_{k+1}(x_{k+1},y_{k+1})

路径方向角：  α_k = atan2(y_{k+1}−y_k, x_{k+1}−x_k)

跨航迹误差（右正左负）：
    e = −(x−x_k)·sin(α_k) + (y−y_k)·cos(α_k)

沿航迹距离：
    s =  (x−x_k)·cos(α_k) + (y−y_k)·sin(α_k)

期望艏向：
    ψ_d = α_k − atan(e / Δ)       Δ 为前视距离
```

**前视距离 Δ 整定**：小则收敛快但易蛇行，大则平滑但误差大。经验值 `Δ = (1.5~3) × 船长`，或速度自适应 `Δ = Δ_min + k·u`。

**积分 LOS（ILOS）——达成亚米级横向误差的必要条件**

纯 LOS 在恒定横流下有稳态跨航迹误差。加积分项：

```
ψ_d = α_k − atan( (e + κ·∫e dt) / Δ )
```

积分项自动累积出**侧偏角（Crab Angle）**，让船头微微顶向流来方向，实现"斜着走直线"。**横向误差要求 ≤0.5 m 时，在 0.5 m/s 流速下没有 ILOS 无法达标。**

**横流补偿的两条路线**

| 方式 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **ILOS 偏转船头**（欠驱动唯一选择） | 能耗低（推力沿航向） | 船头不指向航线方向 | 普通巡航默认 |
| **直接横向推力**（仅全驱动） | 船头始终对准航向，观感好、便于定向载荷作业 | 横向推力持续消耗，能耗高 | 港区巡检等对姿态有要求的场景启用 |

建议做成可配置项。

**航点切换（两条判据都要有）**

```
1. 距离判定： ‖P − P_{k+1}‖ < R_accept
2. 过线判定： s > L_k   （已越过垂直于航线的终点线）
```

**第 2 条必须有**——只用距离判定时，船因扰动没能进入接受半径会绕着航点画圈永不切换。

**转角处理**：① 提前切换 `R_switch = Δ / tan(θ/2)`；② Dubins 圆弧过渡；③ 减速过弯 `u_d = u_nominal · cos(θ/2)`。**建议 ①+③ 组合**。验收时转弯段应从跨航迹误差统计中单独剔除。

## 九、模式管理与安全

### 9.1 模式状态机

```
                  ┌──────────┐
       上电 ────► │  IDLE    │ ◄──── 任务完成 / 急停
                  └────┬─────┘
                       │ 自检通过 + 解锁
              ┌────────┴────────┐
              ▼                 ▼
        ┌──────────┐      ┌──────────┐
        │  MANUAL  │◄────►│   AUTO   │
        │  (遥控)  │ 接管 │  (航线)  │
        └────┬─────┘      └────┬─────┘
             │ 松杆            │ 暂停
             ▼                 ▼
        ┌──────────┐      ┌──────────────────┐
        │ HDG/SPD  │      │  DP (定点)        │
        │(定向定速)│      │  L0→L1→L2 降级    │
        └──────────┘      └────┬─────────────┘
             │                 │
             └────────┬────────┘
                      ▼  失联/低电/进水/围栏/浅水/环境超限
                ┌──────────┐
                │   RTL    │  自动返航
                └──────────┘
```

**三条铁律**

1. **遥控优先级最高**：任何自动模式下，操作员推杆或按接管键**立即**切入 MANUAL
2. **无扰切换（Bumpless Transfer）**：切换瞬间把新控制器积分项初始化为当前实际输出；参考值取当前实测值（切定向时 `ψ_d ← ψ_当前`，切定点时 `η_d ← η_当前`）。否则输出跳变、船会猛窜
3. **模式准入检查**：切入前校验前置条件（GNSS 解状态、差分龄期、电量、传感器健康、推力余量），不满足则拒绝并回报原因，**不允许静默失败**。锁艏向定点的准入条件最严格

### 9.2 安全策略清单

| 触发条件 | 响应动作 | 优先级 |
|---|---|---|
| 急停指令 / 硬件急停 | 立即切断动力（**硬件继电器，不经软件**） | 最高 |
| 舱内进水 | 停车 + 报警 + 全速返航 | 最高 |
| 通信失联 > 3 s | 原地停车（有 RTK 则定点保持） | 高 |
| 通信失联 > 30 s | 自动返航 RTL | 高 |
| 摇杆包超时 > 500 ms | 摇杆量归零 | 高 |
| 风速 / 流速超出设计环境 | 报警 + 自动返航（DP 的 L3） | 高 |
| 推力利用率 > 85% 持续 10 s | 触发 DP 降级（8.2.3） | 高 |
| 电量 < 30% / < 20% | 报警提示返航 / 强制返航（按剩余电量与距离估算） | 中 / 高 |
| 超出地理围栏 | 拒绝外驶 + 返回围栏内 | 高 |
| GNSS 失锁 > 60 s | 停车等待 | 高 |
| 差分龄期 > 5 s | 禁止切入精密定点；已在定点则降级 | 中 |
| 水深 < 0.8 m / < 0.6 m | 限速报警 / 停车原路后退 | 高 |
| 测深数据无效 > 5 s | 限速 + 报警（可能已在盲区） | 高 |
| 单台推进器故障 | 切换降级分配（四推可 4 选 3），限速返航 | 高 |
| 推进器堵转/缠绕（电流高 + 转速低） | 停止该推进器，降级运行 | 高 |
| 上位机失联 | MCU 独立维持当前模式或停车 | 高 |

**看门狗**：MCU 硬件看门狗 + 软件线程心跳，任一控制线程超时未喂狗则安全停机；MCU 与上位机互相监视心跳。

> **构型的安全含义**：四推冗余下单台推进器失效后剩余 3 台仍可产生三自由度控制力（能力下降但不失控），可自主返航；双桨与双吊舱构型无此冗余，单点失效即需人工救援。**这一点应作为构型选择的权重项，并写入验收测试。**

## 十、软件架构与实时性

### 10.1 模块划分

```
【Linux 上位机】非实时
  ├── 地面站通信（MAVLink 编解码、双链路管理、滞回切换）
  ├── NTRIP 客户端（双服务商、断线重连、RTCM 转发）
  ├── 任务管理（航线存储、上传下载、进度跟踪）
  ├── 黑匣子日志（全量数据落盘、时间分片）
  ├── 参数管理（配置版本化、在线下发）
  ├── 水深图与地理围栏管理（5.7 第一层）
  └── [预留] 感知与避障

        ↕ MAVLink over CAN，100 Hz 状态 / 10 Hz 指令

【实时控制 MCU】硬实时
  ├── 传感器驱动（中断 + DMA）
  ├── GNSS/INS 接口（或自研 ESKF）    @200 Hz
  ├── 制导（LOS / DP 参考生成）       @ 20–50 Hz
  ├── 控制（三自由度 PID + 前馈）     @100 Hz
  ├── 推力分配（伪逆 + 饱和 QP）      @100 Hz
  ├── 模式状态机与安全监控            @ 50 Hz
  ├── DP 降级逻辑（8.2.3）            @ 10 Hz
  └── 独立看门狗
```

### 10.2 关键工程约束

- **控制环运行在最高优先级实时任务**，与通信、日志、文件 IO 隔离
- **控制频率 ≥100 Hz，周期抖动 <10%**——抖动比低频更致命，PID 的微分与积分都依赖固定 dt。用硬件定时器触发，不用软件延时
- **安全逻辑独立于上位机**：急停、失联保护放在 MCU，Linux 死机仍能停船
- **参数与代码分离**：增益、限幅、阈值、**推进器布局与安装角**全部走配置文件，支持在线加载与版本管理
- **日志优先级低于控制**：写卡阻塞时丢日志保控制
- **所有浮点防 NaN**：除法前检查分母，`atan2` 前检查零向量。一个 NaN 传到控制输出就是失控
- **QP 求解必须有超时与兜底**：未在规定迭代内收敛立即退回伪逆解 + 等比缩放，**绝不允许阻塞控制周期**

### 10.3 为后续功能预留的接口

在制导层与控制层之间预留**指令仲裁器**，避障/靠泊接入时不触及控制层以下任何代码：

```
   [制导层]                        [后续：感知与避障]
  LOS / DP / 遥控                 雷达/视觉 → 障碍列表、岸壁距离
      │                                │
      │ η_d, u_d（任务期望）             │ 避障建议 / 靠泊期望
      ▼                                ▼
  ┌──────────────────────────────────────────┐
  │           指令仲裁器 Arbiter               │
  │  本期：直通（passthrough）                 │
  │  后续：按优先级覆写，安全 > 避障 > 任务      │
  └────────────────┬─────────────────────────┘
                   ▼  η_cmd, u_cmd
        [控制层] 三自由度 PID  ← 零改动
        [分配层] 推力分配      ← 零改动
```

同时预留：状态总线话题定义（`/perception/obstacles`、`/perception/berth_pose`）、状态机模式枚举位（`AVOIDANCE`、`BERTHING`，暂不可切入）、黑匣子日志的感知数据段（避免后续日志格式不兼容导致历史数据无法回放）。

## 十一、测试与参数整定流程

**必须按顺序来，不要跳步。整定原则：从内到外、从快到慢，内环带宽应比外环高 3~5 倍。**

| 阶段 | 内容 | 通过标准 |
|---|---|---|
| 1. 静态验证 | 传感器检查、坐标转换、杆臂标定、时间同步 | 静止时位置漂移 <5 cm，航向抖动 <0.5° |
| 2. 系泊测试 | 推力标定、推进器方向与安装角标定、分配矩阵验证 | 给定 τ_Y 只横移不转艏；给定 τ_N 只转不移 |
| 3. 链路测试 | 主备链路切换、NTRIP 切换、失联保护、延迟测量 | 端到端延迟达标，切换无失控 |
| 4. 开环航行 | 直通模式手动开船，记录响应 | 辨识时间常数、最大速度、横移与转艏能力 |
| 5. 内环整定 | 角速度环 → 纵向速度环 → 横向速度环 | 阶跃超调 <15%，无持续振荡 |
| 6. 外环整定 | 艏向环 → 位置环 | 30° 阶跃：上升 <5 s，超调 <10%，稳态 <2° |
| 7. 环境力观测器 | 前馈增益、观测器带宽 | 人为拖拽施力，观测值与实测偏差 <20% |
| 8. DP 整定 | 三自由度 PID、死区、降级阈值 | 静水 ±0.2 m / ±2° 保持 10 分钟 |
| 9. 制导整定 | LOS 前视距离、ILOS 积分增益 | 直线段跨航迹误差 RMS <0.3 m，无蛇行 |
| 10. 降级逻辑验证 | 人为限制推力上限，验证 L0→L1→L2→L3 | 各级切换平滑，无跳变，迟滞有效 |
| 11. 故障注入 | 拔天线、断网、断差分、单推进器断电、模拟低电/进水/浅水 | 全部按预期降级，无失控 |
| 12. 综合验收 | 按第十三章指标全项测试 | 全部达标并留存数据 |

**必备工具**

- **黑匣子全量记录**：原始数据 + 控制中间量 + 模式切换事件，出问题能离线复现
- **仿真环境**：先用船体动力学 + 环境干扰模型跑通所有逻辑（尤其状态机与降级边界），再上真船。**能在仿真里发现的 bug 不要拿真船试**——湖里捞船的成本远高于写仿真
- **在线调参**：地面站支持不停船实时改参数

## 附录 A：演进路线

```
V1  五种基本模式 + DP + 安全体系
      ↓ 预留：算力、供电、安装位、软件接口（10.3）
V2  辅助驾驶：毫米波雷达 + 避障决策（VO/DWA）
    自动靠泊：激光/视觉近距定位 + 靠泊控制律
      ↓ 硬件仅需增加传感器
V3  云平台：轨迹上传、远程诊断、OTA、多船管理
```

**本期选型对后续的友好度**：全驱动构型已满足自动靠泊所需的运动能力；若上位机选 RK3588，其 NPU 可支撑轻量检测模型。因此后续大概率只需增加传感器，**不需要更换计算平台或改造船体**。若本期选择欠驱动路线，则自动靠泊功能后续无法通过加装传感器实现，必须改造推进系统——**这是构型决策不可逆的部分，需在第 15.1 节的问题 1、4 中一并考虑。**
